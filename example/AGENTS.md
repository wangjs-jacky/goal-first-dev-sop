# Qv2ray 自建代理学习 · 目标仓库工作约定

本版根据用户确认的方向整理；具体方案随调研和反馈调整，执行进度以各任务 index.md 的 status 为准。

总目标：搭建自己可使用的代理服务；理解核心原理，能排错、能复现。

## 执行与进度

一次推进用户指定的任务，先读该任务 index.md、PROMPT.md 及必要的前置结果。不把生成计划视为执行全部任务的授权。输入或权限不足时说明缺口，不虚构结果；常规实施细节自主处理。

每个任务 index.md 顶部 YAML 只有 status 一个字段：pending 未开始、running 进行中、review 待验收、done 已完成、blocked 受阻。开始、提交验收、验收完成或受阻时由 AI 更新。失败原因与重试过程写正文；不添加百分比、ID 等字段，不新建 PROGRESS.md。查看进度时读取各任务当前状态，不将文件状态当成实时进程监控。

每步结束说明目标是否达成、结果位置和下一步建议。根据反馈调整后续任务；改变目标或预算需用户决定，原始目的与失败尝试保留。

## 沉淀规则

需求统一保存在 problem.md，图片在 assets/ 并用相对路径嵌入；填写稿归 archive/intake/。后续补充保留初始目的和简短变更记录。

每个任务使用 tasks/两位编号-具体内容/，目录内直接放 index.md 和 PROMPT.md，不创建提示词子文件夹。所有执行路径以本目标仓库根目录为基准。

执行后才生成任务内 result.md，写结果、依据、未知项和下一步；笔记放 notes/，证据放 evidence/，多次尝试放 attempts/。结果必须来自实际操作；尝试文件用日期时间和短名称，同名加序号，不覆盖旧尝试。

每次追问回答后，把实际问题与回答记入所属任务的 FAQ.md，注明日期和必要依据，更正留痕。REFERENCES.md 保存资料来源、用途和核验情况；IDEA.md 保存灵感、提出者及当前态度，默认暂存，不自动执行。整体需求内容归根目录，具体任务内容归任务目录。首次有内容才创建文件并补入口链接，不制造空记录。

跨任务只引用所需资料，Markdown 链接相对于当前文件。凭据不进 Git，截图和日志先脱敏。需要迁移知识库、购买或修改其他系统时遵循用户的实际授权。

## 文件怎么沉淀

[追问与回答 FAQ.md](FAQ.md) · [资料索引 REFERENCES.md](REFERENCES.md) · [灵感与优化点 IDEA.md](IDEA.md)

整体需求的记录放在这里；某个 Task 内发生的问答、资料和灵感，则保存到该 Task 的同名文件，首次有内容时由 AI 创建并补索引。每次追问回答后自动记录；想法先暂存，采纳后才进入任务。

你只需修改需求或给出反馈；由 AI 把执行中产生的内容放回对应 Task。每个 Task 的 index.md 是该任务状态和产物链接的唯一入口，总览不重复维护状态。

```text
目标仓库/
  problem.md                   初始目的与整理后的需求
  assets/                      需求图片等附件
  archive/intake/              原填写稿（保留追溯）
  AGENTS.md                    总流程与任务入口
  tasks/01-调研朋友的方案/                    每个 Task 都使用同样的结构
    index.md                   目标、状态、产物链接、简短记录
    PROMPT.md                  可直接交给独立 AI 的完整指令
    result.md                  当前结果和下一步交接（执行后生成）
    FAQ.md                     追问与实际回答（首次出现时创建）
    REFERENCES.md              资料来源、用途和核验情况（按需创建）
    IDEA.md                    灵感与优化点，不自动执行（按需创建）
    notes/                     调研材料、学习笔记（按需创建）
    evidence/                  脱敏截图、日志和验证记录（按需创建）
    attempts/                  多次 POC、失败尝试及修复记录（按需创建）
```

只保存实际产生的内容，不预先创建一堆空文件。尝试记录使用 `YYYYMMDD-HHMM-简短说明.md`；已有同名文件就增加序号，不覆盖。`result.md` 可以更新当前结论，旧尝试和失败证据保留。其他 Task 引用前置结果路径，不复制全部上下文。

本目录是目标仓库根目录；所有任务指令相对于这里解析，迁移后不需要父目录工程文件。入口为本目录 `PROMPT.md`。

凭据不进 Git。资料只归属到一个 Task，其他地方用链接。全流程的最终指南也放在 05 目录内；当前不写入 Obsidian。

需求阶段的图片等附件归 `assets/`，嵌入 `problem.md`；任务执行产生的图片和记录才归对应 Task。原填写稿已移至 [archive/intake/problem.template.md](archive/intake/problem.template.md)，便于追溯，但后续统一读取正式需求。
