# 04 · 验证实际使用

复制下面整段给已打开本仓库的独立 AI。

```text
执行 example 的 04 使用验证。所有路径以仓库根目录为基准。先读取 AGENTS.md、example/problem.md、example/index.md、example/tasks/04/index.md 与 example/tasks/03/result.md。有本任务结果时先读，避免重复验证。部署尚未完成时返回 03 处理缺口。

目标：确认服务在用户的目标设备上满足实际使用需求，而不只是显示“连接成功”。

结合真实设备、应用或网站，与用户补齐少量具体使用场景。验证前写清入口、需要的权限、操作步骤和预期结果。至少考虑目标访问、预期出口、断线重连和服务重启恢复；根据实际需求调整，不增加无关的大型测试。重启或断网测试须在允许影响使用的时间和范围内进行。

实际执行并记录预期与观察结果；无法在目标设备验证时请用户按明确步骤操作并反馈，注明证据来自用户。未执行就是未验证，单凭配置文件不能判定通过。出现问题记录复现方式与线索，交回 03 修复；修复后复验受影响项目。不要擅自改变已经选定的架构。

将成果保存在 example/tasks/04/：result.md 写场景、环境、步骤、实际结果、通过/失败/未验证项及遗留问题；脱敏截图或日志放 evidence/，复验与失败记录放 attempts/。在 index.md 更新状态、产物索引，追加时间、执行者、状态变化与用户反馈。不复制 03 的整份部署笔记，引用所需路径即可。

完成标准：约定的关键使用场景实际通过，或剩余限制已向用户说明并获得接受，未通过项仍如实保留。结束时交回结果路径与 05 学习整理建议，不用短时连通承诺长期稳定，不自动开始下一个 Task。
```
