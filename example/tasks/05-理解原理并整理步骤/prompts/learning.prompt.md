# 05 · 理解原理并整理步骤

复制下面整段给已打开本仓库的独立 AI。

```text
执行 example 的 05 学习整理。所有路径以仓库根目录为基准。先读取 AGENTS.md、example/problem.md、example/index.md、example/tasks/05-理解原理并整理步骤/index.md 和 example/tasks/04-验证实际使用/result.md。按需要引用 01 的原理说明、03 的实际步骤与各 Task 中的失败记录，不一次读取所有材料。若系统还有关键问题未解决，先说明它如何影响学习与复现。

目标：用户能解释核心链路、做基本排错，并依据指南重新搭建；同时得到一份基于真实操作的新手指南。

先用已跑通的方案讲清应用、客户端、代理核心、服务端和目标站点之间的关系，用简单文字线框图辅助。根据用户已有基础解释关键概念，不把泛泛知识点堆成教程。请用户用自己的话讲解核心流程，再选择一个不影响现有服务的基础排错场景让用户练习，记录真实回答和卡点；不要由 AI 代答后宣称用户已掌握。

从实际验证过的步骤整理指南，包含前提、操作顺序、关键原因、预期结果、常见故障与恢复方法。只引用真实版本和证据，未复现步骤标明状态。不为验证学习效果而擅自重建、删除或中断正在使用的服务；复现练习需要合适的隔离环境和用户授权。

成果全部保存在 example/tasks/05-理解原理并整理步骤/：guide.md 放新手指南，result.md 记录学习结果、用户反馈、仍需练习的点及总目标完成情况；补充笔记放 notes/，练习或复现记录放 attempts/，脱敏证据放 evidence/。在 index.md 更新状态、产物索引，追加时间、执行者与进展。其他 Task 的文件用相对链接引用，不复制全部历史，不直接写入 Obsidian。

完成标准：指南依据已验证步骤，用户实际讲解与排错有记录。尚未进行独立复现时必须标明，不宣称“能独立复现”已经验证。结束时给出指南与结果路径，并说明总目标哪些已达成、哪些还待验证；需要时再由用户决定是否整理正式 SOP 或迁移到 Obsidian。
```
