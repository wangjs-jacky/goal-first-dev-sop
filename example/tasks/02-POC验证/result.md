# POC 结果 · 2026-10-12

结论：**现有环境的最小链路验证通过，自建路线有条件可行。** 不是已经搭建好自己的服务。完整证据与复现方法见 [本次尝试](attempts/20261012-1000-现有环境最小链路.md)。

## 已验证

- HTTP 与 SOCKS5h 两种接入均成功，目标端观察到的出口都是朋友服务器。
- 禁用显式代理后，请求出口不同，直连与代理路径确有区别。
- Cloudflare 入口 TLS 证书校验通过，无需关闭证书验证。
- 经本机代理访问随机回环端口，确实命中本机临时服务，私网直连场景通过。

## 推荐路线

```text
现有 Mac mini / Qv2ray + V2Ray（先不换客户端）
                     ↓ VLESS / WebSocket / TLS
自己的域名 + Cloudflare 入口
                     ↓ 正确回源配置
自己的 VPS / Xray
                     ↓
目标网站
```

理由：现有客户端、协议组合及入口方式有真实可用证据，复用可以减少同时变化的组件。WARP、复杂分流、新客户端和其他协议不纳入最小部署。

服务端核心优先围绕 Xray 做最小部署；面板不是流量链路必需品。朋友的 x-ui-yg 二进制未开源，不能因为连接测试通过就认定其供应链安全。后续建议采用可核验来源的官方核心和最小配置；若保留 x-ui-yg，则须明确接受其二进制信任边界。该实现选择尚未安装验证，不把它记为已复现路线。

## 03 开始部署前的条件

1. 购买前确定预算、地区和计费边界；本轮未下单，不假定用户已授权付款。
2. 自有域名及 Cloudflare 配置权限就绪；不能借用朋友的域名、账号或节点密钥。缺少这些时 CDN 路线仍未具备部署条件。
3. 新 VPS 上确认系统、架构、SSH 管理与最小防火墙规则，选择来源可核验的核心版本。不要直接运行停防火墙的安装功能。
4. 配好域名、节点证书、WS 参数和 Cloudflare 回源，核验客户端到边缘及边缘到源站的 TLS；不能把本次边缘 TLS 测试替代回源验证。
5. 将“新实例首次连接、出口与自有服务器一致”作为 03 的首个实际验收闭环。现有旧客户端若与新核心配置不兼容，再在隔离环境验证维护中的替代客户端，不破坏现有连接。

当前推荐是技术路线，不代表预算、账号准备或闭源面板选择已获接受。03 仍未启动。

## 留待后续验证

国内分流的全面行为、实际 DNS 路径/泄漏、目标应用覆盖、连接中断恢复、服务重启恢复和长期稳定性尚未通过测试。WARP 不在最小需求中，没有测试。朋友服务器 SSH 仍未进入；其详细系统配置不是本轮复制安装的依据。
