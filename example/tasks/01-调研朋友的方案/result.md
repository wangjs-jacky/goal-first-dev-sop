# 调研结果 · 2026-10-12

已完成公开资料研究和面板配置的只读核对，提交用户验收；尚未完成端到端连接验证或主机级检查。以下当前结论取代文末早期阶段认识。

## 结论先看

朋友当前面板返回两个启用的 **VLESS + WebSocket + TLS** 入站，端口为 8443、2096；面板报告 Xray 运行中，版本为 26.2.6。这说明配置与面板报告状态，不等于已经证明客户端可用。

Qv2ray 是本机客户端前端，不是服务器面板。其官方 README 明确停止维护，最后稳定版为 2021 年的 v2.7.0；适合当作学习入口，不宜未经兼容验证直接定为新方案。x-ui-yg 的 README 则明确说明“二进制文件未开源”，公开安装脚本不等于整个运行程序可审计。

## 核心流程

```text
管理链（不承载代理业务流量）
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ x-ui-yg 安装 │ →  │ x-ui 管理面板│ →  │ Xray 配置/进程│
└──────────────┘    └──────────────┘    └──────────────┘

流量链（本次未实际连接验证）
┌──────────────────────┐
│ 浏览器或其他应用       │
└──────────┬───────────┘
           ↓ 应用代理 / 系统代理 / TUN 等方式接入，待选
┌──────────────────────┐
│ 本机客户端 + 代理核心  │
└──────────┬───────────┘
           ↓ VLESS / WebSocket / TLS
           ↓ 是否经过 CDN 或反向代理，尚未确认
┌──────────────────────┐
│ VPS 上的 Xray 入站     │
│ 识别请求 → 路由 → 出站 │
└──────────┬───────────┘
           ↓
┌──────────────────────┐
│ 目标网站              │
└──────────────────────┘
```

VPS 提供运行环境和出口；面板负责管理；Xray 才负责实际转发。VLESS 负责代理请求及用户认证，WebSocket 是承载方式，TLS 保护客户端到 TLS 终止点的传输。朋友节点的 VLESS `decryption` 为 `none`，不能据此认为整条连接不加密：它同时配置了 TLS。

客户端前端负责导入节点和控制本机核心；应用是否真正走代理取决于接入方式。此类代理不自动等于覆盖整台设备的传统 VPN。DNS 决定域名如何解析，路由决定流量使用哪个出口，两者都需要独立验证。

## 实际核对到了什么

| 项目 | 核对结果 | 边界 |
|---|---|---|
| 两个入站 | 启用、VLESS、WS、TLS，各一个客户端 | 未保存 UUID 或 WS 路径 |
| TLS 配置 | 各有一个证书配置，最低 TLS 1.2 | 未验证证书有效性、域名匹配或真实握手 |
| 核心状态 | 面板报告 running、26.2.6 | 未在主机上独立核验进程 |
| 管理入口 | HTTP；面板证书配置为空 | 节点 TLS 不会保护这条管理连接 |
| 路由模板 | 有 direct、阻断、SOCKS/WireGuard 等 WARP 相关出站；含 UDP 443 阻断规则，兜底 direct | 有模板不等于 WARP 正在工作或命中实际流量 |
| DNS | 模板未显式配置 DNS，domainStrategy 为 AsIs | 不能由此确定系统或客户端的实际 DNS 行为 |
| SSH | 到达认证阶段，但认证失败 | 未进入系统，未核对 OS、防火墙、文件或服务单元 |

依据：[脱敏检查记录](evidence/20261012-panel-readonly.md)。未修改服务、安装程序、重启进程或进行购买。

## 对后续方案的影响

- **先复现最小连接，再决定搭建路线。** 不必一开始复制 WARP、复杂分流和全部脚本功能。
- **客户端需重新选型验证。** Qv2ray v2.7.0 的 macOS 包为 x64；v2rayN 当前公开版本 7.25.4 提供 macOS arm64 包，可列为候选，但本次没有安装或测试，用户设备也尚未确认。
- **不能把 x-ui-yg 称为完整开源实现。** 已阅读的安装脚本会下载二进制、安装服务，部分下载使用 `--insecure`，脚本含停用防火墙的功能；本次没有执行，也不是完整安全审计。之后选用前要确认信任与最小暴露面。
- **管理面板需单独保护。** 自建时优先考虑 HTTPS 或 SSH 隧道，不沿用公网 HTTP 登录方式。本轮不改朋友的环境；已通过聊天提供的管理密码建议由管理员更换，后续走安全渠道提供。
- **文档必须匹配版本。** 新版 Xray 文档字段与本次面板生成格式存在差异，不把最新 JSON 直接粘贴进当前环境。官方 WS 文档推荐考虑 XHTTP，但这不是本轮自动迁移协议的理由。

## 下一步只建议两个 POC

1. **最小连接 POC：证明目标设备能使用现有节点。** 确认设备/系统和允许测试的目标站点，安全取得节点信息，核对客户端兼容性、证书域名和 WS 参数；验证访问与预期出口。记录版本、步骤、结果和失败点，不先买服务器。
2. **流量路径 POC：证明“哪些流量走哪里”。** 选择一个应走代理和一个应直连的场景，核对应用覆盖、DNS 与分流结果。仅在目标需要时再验证 WARP；失败则回到对应参数或路线调整。

## 当前认识

`x-ui-yg` 是服务端的安装与管理面板方案；它负责在 VPS 上管理代理核心与入站节点。Qv2ray 是用户设备上的客户端前端，两者不属于同一层。截图只表明面板当时展示了两个已启用的 VLESS 入站，不能证明具体传输方式、TLS 设置或服务当前连通。

目标站点
