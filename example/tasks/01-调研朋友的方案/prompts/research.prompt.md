# 01 · 调研朋友的方案

复制下面整段给已打开本仓库的独立 AI。

```text
执行 example 的 01 调研。所有路径以仓库根目录为基准。先读取 AGENTS.md、example/problem.md、example/index.md 和 example/tasks/01-调研朋友的方案/index.md；有该任务 result.md 时先读取，接着已有进度做，不重复调研。

目标：弄清朋友的服务如何工作，形成能看懂的核心流程、组件职责和待验证问题，为下一步 POC 提供依据。Qv2ray 是学习入口，不预先认定它必须作为最终客户端。

从需求里的 yonggekkk/x-ui-yg 项目和已提供的部署信息入手。先研究公开文档和实现，核验项目及相关客户端的维护、版本和兼容情况。已有服务器与面板入口可用作调研线索；要核验实际部署，先确认当前授权覆盖对朋友服务器的只读检查，并通过私密渠道取得所需凭据。缺少权限或凭据时继续公开资料调研，并标明实际部署未核实。不改配置、不安装、不重启服务，不把截图中的端口推断为 TLS 或传输方式。

思考顺序可以是：有哪些组件 → 请求如何走到目标站点 → 朋友实际用了哪些设置 → 哪些能直接参考、哪些需要验证。按需要解释面板、核心、协议、传输、TLS、DNS/路由和客户端的角色，不为凑内容逐项展开。流程用简单文字线框图呈现。

将成果保存在 example/tasks/01-调研朋友的方案/：result.md 写核心流程、来源、已核实事实、未知项及建议的少量 POC；细节按需放 notes/，脱敏证据放 evidence/，阶段尝试放 attempts/。在 index.md 更新状态和产物索引，并追加时间、执行者、进展及用户反馈。不要把凭据写入任何受 Git 跟踪的文件。

完成标准：用户能从结果中看懂各组件如何配合，关键说法有来源，未核实部分明确，下一步知道要验证什么。实际部署不可访问时交付部分结果并标明缺口，不声称已完整核实。结束时给出结果路径及 02 建议，等待反馈；不购买服务器、不执行下一项 Task。
```
