## 实施顺序

1. 核对全域 TLS 既有 Full 自动模式；Page Rules 新建界面已无 SSL 选项，因此使用官方 Configuration Rules。只匹配 node 主机，配置 SSL Strict。DNS 尚未存在时确认“仍部署”，随后补对应代理记录。
2. 在 Mac mini 生成专用 SSH 密钥，通过该实例开通邮件在内存取得初始密码、仅追加公钥至 root authorized_keys。新密钥单独连接验收成功，未删除旧密钥或禁用密码登录。
3. VPS 本地产生 RSA2048 私钥与 CSR；将 CSR 交 Cloudflare 签发证书，移除默认通配符和根域，仅保留 node.paws.rodeo。私钥从未离开 VPS。
4. 执行 [已实施的安装脚本](deploy-node.sh)，固定官方核心版本和发布包摘要；生成全新 UUID/WS路径，安装最小非 root systemd 服务，不安装管理面板。
5. 用 Cloudflare Origin RSA CA 验证证书链和主机名。证书到期日 **2041-10-08 06:28 UTC**；Cloudflare 不主动提供该类证书到期通知，后续需自主管理，到期前重签；私钥若泄露需立即轮换。
6. 执行 [已实施的独立防火墙脚本](guard-node.sh)，从官方 ips-v4/ips-v6 获取回源网段，保留管理连接并验证防锁出恢复。规则网段为部署当天快照，未来 Cloudflare 变更网段时需更新，不静默自动抓取覆盖。
7. DNS 新增 A node → 新 VPS，橙云开启。WebSockets 既有开关已开启；没有 Worker Routes，无需修改。
8. 运行 [隔离验证脚本](verify-node.mjs)，新出口与目标访问通过；临时测试进程已停止。完整结果见[证据](../evidence/20261012-node首次连接.md)。

这些脚本是本次实例的审计记录，有目标主机/空配置保护，不应在别的服务器或已部署实例上直接重跑。

## 恢复边界

- 停止新代理：`systemctl stop xray-node`，不影响 SSH，也不会修改本机旧代理。
- 防火墙紧急恢复：`systemctl stop node-guard` 只删除本次专用表，不清空其他规则；恢复访问后排查。停机并不停止 RackNerd 年付计费。
- Cloudflare 回退只涉及新增 node A记录、node 专用规则；不改全域 TLS，不删其他域名记录。Origin CA 证书如撤销不可逆，单独确认后再做。
- 临时服务配置修改前另做受限权限备份；本次没有源站旧配置可覆盖。
- SSH 主机密钥使用此前首次连接已信任的 known_hosts，未做供应商独立渠道指纹比对，仍有首次信任边界。
